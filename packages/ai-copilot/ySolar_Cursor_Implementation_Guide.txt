1. Project Overview & Scope
This document is the single source of truth for building the ySolar AI Copilot in Python. The teammate team owns the Hedera smart contracts and the React UI. This codebase owns: the 0G inference integration, two-mode agent logic (Ask and Trade), the off-chain intent store, and the REST API that the UI calls.


NOT in scope: Hedera smart contracts, React frontend, QuickNode telemetry ingestion, ADI Chain vault, Hedera Schedule Service.


IN scope: A Python FastAPI service running the AI agent, managing conversation state, validating trade intents, and exposing REST endpoints consumed by the React UI and that trigger on-chain writeOption() calls.


2. Architecture
2.1 Two-Mode Agent (Cursor-Style)
The agent has two modes sharing the same 0G inference model and the same conversation history. Only the system prompt changes on mode switch. Context is NEVER cleared.


Property
	ASK Mode
	TRADE Mode
	Purpose
	Conversational analyst. Explore strategies, reason about telemetry.
	Execution terminal. Parse intent, validate, output writeOption() JSON.
	System Prompt
	Loose, analytical. Verbose encouraged. Step-by-step reasoning.
	Strict. Output ONLY valid JSON. Ask one question if ambiguous. Never guess.
	Output
	Natural language. Markdown OK.
	JSON intent object + one-sentence confirmation.
	Transactions
	None. Read-only.
	Produces validated intent -> triggers /intents/submit on user confirmation.
	Temperature
	0.7 — exploratory
	0.2 — precise and deterministic
	

2.2 Context Switching Behaviour
When the UI flips the mode toggle, it sends the new mode on the next /chat request. The backend detects the change, swaps the system prompt, and appends a handoff instruction: 'Review the conversation above, extract the trade parameters discussed, summarise them for the user, and ask for confirmation before generating the JSON payload.' The history is untouched.


The UI inserts a visual divider in the thread: '-- switched to TRADE MODE --'. This is UI-only; the backend does not store this marker.

import os

def get_0g_client() -> OpenAI:
    global _a0g, _client
    if _client is None:
        _a0g = A0G(
            private_key=os.environ['A0G_PRIVATE_KEY'],
            rpc_url=os.environ['A0G_RPC_URL']
        )
        provider = os.environ['A0G_PROVIDER_ADDRESS']
        _client = _a0g.get_openai_client(provider)
    return _client

7. Agent Logic — agents/agent.py
from agents.client import get_0g_client
from agents.prompts import ASK_SYSTEM_PROMPT, TRADE_SYSTEM_PROMPT, TRADE_CONTEXT_HANDOFF
import json, os


MODEL = os.environ.get('A0G_MODEL', 'qwen-2.5-7b-instruct')


class AgentSession:
    def __init__(self, session_id: str):
        self.session_id = session_id
        self.mode = 'ask'
        self.last_mode = 'ask'
        self.history: list[dict] = []


    def switch_mode(self, new_mode: str):
        self.last_mode = self.mode
        self.mode = new_mode


    def _build_messages(self, user_message: str) -> list[dict]:
        if self.mode == 'trade':
            system = TRADE_SYSTEM_PROMPT
            # First Trade message after Ask: append handoff instruction
            if self.last_mode == 'ask' and len(self.history) > 0:
                system += '' + TRADE_CONTEXT_HANDOFF
        else:
            system = ASK_SYSTEM_PROMPT
        messages = [{'role': 'system', 'content': system}]
        messages += self.history
        messages.append({'role': 'user', 'content': user_message})
        return messages


    def chat(self, user_message: str) -> dict:
        client = get_0g_client()
        messages = self._build_messages(user_message)
        response = client.chat.completions.create(
            model=MODEL,
            messages=messages,
            temperature=0.2 if self.mode == 'trade' else 0.7,
            max_tokens=1024,
        )
        content = response.choices[0].message.content
        self.history.append({'role': 'user', 'content': user_message})
        self.history.append({'role': 'assistant', 'content': content})
        self.last_mode = self.mode
        intent = _try_extract_intent(content) if self.mode == 'trade' else None
        return {'content': content, 'mode': self.mode, 'intent': intent}


def _try_extract_intent(text: str) -> dict | None:
    try:
        start = text.index('{')
        end = text.rindex('}') + 1
        return json.loads(text[start:end])
    except (ValueError, json.JSONDecodeError):
        return None


_sessions: dict[str, AgentSession] = {}


def get_or_create_session(sid: str) -> AgentSession:
    if sid not in _sessions:
        _sessions[sid] = AgentSession(sid)
    return _sessions[sid]


8. Intent Schema — intents/schema.py
Mirrors the teammate's intent schema and enforces on-chain contract constraints (expiry >= now + 180, positive integers).


from pydantic import BaseModel, field_validator
from enum import Enum
import uuid, time


class IntentStatus(str, Enum):
    draft = 'draft'
    approved = 'approved'
    submitted = 'submitted'
    confirmed = 'confirmed'
    failed = 'failed'


class TradeIntent(BaseModel):
    intent_id: str = ''
    writer: str
    buyer: str
    product: str = 'covered_call'
    underlying: str = 'ySOLAR'
    amount: int
    strike: int
    expiry: int
    status: IntentStatus = IntentStatus.draft
    tx_hash: str | None = None


    @field_validator('amount', 'strike')
    def must_be_positive(cls, v):
        if v <= 0: raise ValueError('must be positive')
        return v


    @field_validator('expiry')
    def must_be_future(cls, v):
        if v < int(time.time()) + 180:
            raise ValueError('expiry must be at least 180 seconds from now')
        return v


    def model_post_init(self, __context):
        if not self.intent_id:
            self.intent_id = str(uuid.uuid4())

from intents.schema import TradeIntent


_intents: dict[str, TradeIntent] = {}


def save_intent(i: TradeIntent) -> TradeIntent:
    _intents[i.intent_id] = i
    return i


def get_intent(intent_id: str) -> TradeIntent | None:
    return _intents.get(intent_id)


def update_status(intent_id: str, status: str, tx_hash: str | None = None):
    i = _intents.get(intent_id)
    if i:
        i.status = status
        if tx_hash: i.tx_hash = tx_hash


9. REST API Endpoints
9.1 routers/chat.py — POST /chat
from fastapi import APIRouter
from pydantic import BaseModel
from agents.agent import get_or_create_session


router = APIRouter()


class ChatRequest(BaseModel):
    session_id: str
    message: str
    mode: str = 'ask'   # UI sends current toggle state on every message


@router.post('/chat')
async def chat(req: ChatRequest):
    session = get_or_create_session(req.session_id)
    if session.mode != req.mode:
        session.switch_mode(req.mode)
    result = session.chat(req.message)
    return {
        'session_id': req.session_id,
        'mode': result['mode'],
        'content': result['content'],
        'intent': result.get('intent')  # None in Ask; JSON object in Trade
    }


9.2 routers/intents.py
from fastapi import APIRouter, HTTPException
from intents.schema import TradeIntent
from intents.store import save_intent, get_intent, update_status
from hedera.client import submit_to_hedera


router = APIRouter(prefix='/intents')


@router.post('')
async def create_intent(data: dict):
    intent = TradeIntent(**data)
    return save_intent(intent).model_dump()


@router.get('/{intent_id}')
async def get(intent_id: str):
    intent = get_intent(intent_id)
    if not intent: raise HTTPException(404, 'Not found')
    return intent.model_dump()


@router.post('/{intent_id}/submit')
async def submit(intent_id: str):
    intent = get_intent(intent_id)
    if not intent: raise HTTPException(404, 'Not found')
    if intent.status not in ['draft', 'approved']:
        raise HTTPException(400, f'Cannot submit status={intent.status}')
    result = await submit_to_hedera(intent)
    update_status(intent_id, result['status'], result.get('tx_hash'))
    return get_intent(intent_id).model_dump()


10. Hedera API Client — hedera/client.py
Wraps the teammate's Hedera backend. Maps our intent object to their writeOption() call. Confirm the exact endpoint path with the Hedera teammate — update HEDERA_API_BASE_URL once they deploy.


import httpx, os
from intents.schema import TradeIntent


BASE = os.environ.get('HEDERA_API_BASE_URL', 'http://localhost:3001')


async def submit_to_hedera(intent: TradeIntent) -> dict:
    payload = {
        'buyer': intent.buyer,
        'amount': str(intent.amount),
        'strike': str(intent.strike),
        'expiry': intent.expiry,
    }
    async with httpx.AsyncClient(timeout=30.0) as client:
        try:
            # Confirm endpoint path with Hedera teammate
            r = await client.post(f'{BASE}/write-option', json=payload)
            r.raise_for_status()
            data = r.json()
            return {'status': 'submitted', 'tx_hash': data.get('txHash')}
        except httpx.HTTPError as e:
            return {'status': 'failed', 'error': str(e)}

12. UI Integration Contract (Share with React team)
12.1 Chat Flow
* UI calls POST /chat with { session_id, message, mode } on every send
* session_id: generated by UI on page load (e.g. crypto.randomUUID()), stored in React state
* mode: 'ask' or 'trade' — UI sends the current toggle state on every message
* Response: { session_id, mode, content, intent }
* intent is null in Ask mode. In Trade mode it is either null (model asking a clarifying question) or a JSON object with the extracted parameters.


12.2 Trade Execution Flow
1. When intent is non-null in a Trade-mode response, render the JSON as a formatted code block in the chat bubble.
2. Show a 'SIGN & BROADCAST' button beneath the code block.
3. On click, POST /intents with the intent JSON as the body. Receive back an object with intent_id and status='draft'.
4. Immediately POST /intents/{intent_id}/submit to trigger on-chain execution.
5. Poll GET /intents/{intent_id} every 2 seconds until status is 'confirmed' or 'failed'. Update UI accordingly.


12.3 Mode Switch
When the toggle changes, the UI should: (1) insert a system message divider in the chat thread, (2) send the next user message with the new mode value. The backend detects the change automatically. No separate mode-switch endpoint needed.

14. Known Risks & Mitigations


Risk
	Likelihood
	Mitigation
	a0g package has Node.js issues
	Medium
	Use the plain OpenAI fallback client (Section 5.2). Same interface, no Node dependency.
	0G Galileo provider offline at demo time
	Medium
	Test provider 1hr before. Keep OpenAI or Claude as a 2-min fallback (same code, change base_url and api_key).
	Qwen model outputs malformed JSON in Trade mode
	Medium
	_try_extract_intent() handles this gracefully. The model will re-ask. Low temperature (0.2) reduces frequency.
	Hedera teammate API not ready in time
	Low
	Use the mock return value in hedera/client.py. Demo still shows the full AI flow end-to-end.
	Session lost on server restart
	Expected
	In-memory by design. Do not restart during demo. Optionally persist to SQLite with a 30-min migration.
